# CEO Review

Not a rubber stamp. Find the landmines and the real problem before committing engineering time.

## Step 1 — Premise Challenge
- What user problem does this solve, one sentence?
- Is this the real problem, or a symptom of one?
- What's the smallest version that tests the value?

## Step 2 — Pick a mode (ask the user, don't guess)
- **EXPAND** — dream bigger. Present each expansion as an explicit opt-in. Never silently add scope.
- **SELECTIVE** — hold current scope as baseline, surface expansion ideas separately, user cherry-picks.
- **HOLD** — scope is accepted. Make it bulletproof. Don't add or cut.
- **CUT** — strip to the minimum that ships the core outcome.

Once picked, commit to it for the rest of the review. Don't drift to a different mode mid-review.

## Step 3 — Verdict
GREENLIGHT / SHRINK / KILL + one-line reason.
GREENLIGHT or SHRINK → hand off to `/plan-eng-review`.
If a scope change surfaces that isn't this task: log it in IDEAS.md, don't fold it in silently — Scope Lock Protocol applies here too.
